## Overall Impression

A deeply authored instrument that clears the specificity bar decisively and photographs beautifully — the wound→burn→manifest cycle is portfolio-grade. Its weaknesses are not visual: the marquee behavior hides behind a threshold set to the slider's own maximum, a tuning session can be destroyed by one click with no undo, and the URL — the lab's stated deliverable — has no affordance anywhere in the UI. The single biggest opportunity: make the instrument teach and preserve the very thing it exists to produce.

## What's Working

1. **The measuring DOM as composition.** Judging the effect against the site's real type ramp simultaneously, with per-row grain counts and a deliberately sacrificial below-the-floor row, is exactly right for the decision being made.
2. **Help text that teaches trade-offs, not features.** "Pays for the area in opacity, so a wound reads as scatter, not as extra light." The panel documents design reasoning — what an Operate surface for a designer-engineer should do.
3. **Capture-grade reproducibility.** Hash-diffed state, clamped ingestion, deterministic `t0` scrub, `dbg` state counts, a demo choreographed to put wound, recovery, and vessel on camera. Single 78KB file, fonts as the only external requests.

## Priority Issues

1. **[P1] First-contact dead zone.** `minv` defaults to 900 px/s — the slider's max — so the marquee behavior is gated behind a gesture most first sweeps won't produce; the "slowly, then fast" instruction and the `d` auto-sweep both sit below ten sections of scroll. **Why:** the lab's peak experience is discovered by accident or not at all. **Fix:** render the HUD velocity as `412 / 900 px/s`, tinting accent when the gate is crossed; surface auto-sweep as a small HUD affordance. **Suggested command:** /impeccable onboard
2. **[P1] No undo, destructive Reset.** One click discards a whole tuning session; `replaceState` means even the back button can't recover. **Why:** the operator's costliest error has no recovery path in a tool whose output is the accumulated state. **Fix:** stash the pre-reset hash and make the button reset/undo for one cycle, or move the hash writer to `pushState` so browser history becomes the undo stack. **Suggested command:** /impeccable harden
3. **[P2] The deliverable has no affordance.** The URL is the output, yet nothing says so or exports it. **Why:** sessions end flat and states get lost; peak-end rule works against the lab. **Fix:** "copy state · N changed" button beside Reset with a copied flash. **Suggested command:** /impeccable polish
4. **[P2] Keyboard tuning ejects focus.** Every slider blurs on `change`, which Chrome fires per arrow-key step, so precise keyboard tuning is broken for all ~44 sliders. **Why:** the most precise input method self-cancels after one step. **Fix:** blur on `pointerup` only. **Suggested command:** /impeccable harden
5. **[P2] Stale `uRes` skews the lab's own photographs.** `resize()` runs only at boot/resize, so in headless captures grains render ~10% offset from DOM furniture — row labels read against the wrong band in the documented screenshot workflow. **Fix:** call `resize()` at the top of `seed()`. **Suggested command:** /impeccable polish

## Persona Red Flags

**Alex (power user):** wounds immediately (fast flicks clear 900), then must scroll past five sections to Manifest and assemble the timing of four time-shaped sliders (Loose life → Burn-out → Regrow lag → Manifest time) from four help lines; `space`/`d` replay triggers are hidden in the footer; arrow-key precision is ejected by blur-on-change; no section jump-nav, headers not sticky.

**Jordan (first-timer):** greeted by the jargon-first "Locked in" preamble; a gentle sweep produces only aura — the 900 threshold silently swallows the gesture with no HUD comparison point; the curriculum line is in the footer; dragging Manifest sliders in a settled field changes nothing visible, and nothing nearby says "make a wound to see this." Likely outcome: drags Density (instant feedback), concludes the rest is broken, leaves.

## Minor Observations

- Panel section headers (10px, 0.55α) are visually weaker than the controls they organize — inverted scanning hierarchy; only the title is sticky.
- The 10px/0.55α help text is the smallest type carrying the most words, at roughly AA-threshold contrast; one shade or 1px up costs nothing.
- Ten locked light-rig values are hash-settable with no controls — deliberate and commented, but in tension with the project's standing "every value gets a control" rule; a pasted `bump=3` becomes state the panel can't show.
- `demo=1` serializes into the hash: a URL saved mid-demo ships a permanently auto-sweeping lab.
- HUD's "throw · manifest" fragment is static decoration in an otherwise-live telemetry strip.
- Vestigial `'f' → reset()` branch in control wiring has no takers in CTL — dead code.
- `#keys` footer's `margin-top:auto` is overridden by a later `margin:0`; on a tall viewport with a short panel it would float.
- 18 em-dashes in panel prose (detector, advisory) — the authored voice leans on one punctuation mark.
- Reduced-motion exempts the sim deliberately (rationale lives only in a source comment); a11y positives: `label[for]`/`output` pairs, `focus-visible`, `aria-pressed`, semantic structure.

## Questions to Consider

1. If the URL is the deliverable, why is the address bar the only place it exists? A lab whose output is a diff could render that diff — "7 values off default", named, copyable, comparable against a second hash — and become an A/B instrument.
2. What if every section header carried a tiny probe trigger — a canned sweep for Wound/Manifest, a wall-strike for Vessel — so no slider could ever be a silent no-op?
3. Is minv=900 the actual product behavior being tuned, or a demo-preservation setting no real portfolio visitor will cross — meaning the lab is tuning a state the site will rarely enter?
