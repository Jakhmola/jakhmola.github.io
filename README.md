# jakhmola.github.io

A self-updating portfolio at **https://jakhmola.github.io**. The site is never edited by hand: a **Scheduled Rebuild** (GitHub Actions — daily cron, manual dispatch, or any push to `main`) regenerates it from the GitHub API and redeploys to GitHub Pages.

## How it works

```
fetch repos ──> filter ──> rank ──> summarize Featured ──> render ──> deploy dist/
 (GitHub API)  (no forks,  (pure    (GitHub Models LLM,    (static     (Pages, from
                profile,    score)   cached by README hash)  HTML/CSS)   the Actions
                hidden)                                                  artifact)
```

- **Ranking** is a pure function scoring README depth, description presence, push recency, and stars. The top ~5 become **Featured Projects** and reach the page; everything else is left to the "all repos on github" link.
- **Summaries** are two recruiter-oriented sentences per Featured Project, generated by the free GitHub Models endpoint with the workflow's own `GITHUB_TOKEN` and cached in `.cache/summaries.json` (persisted via `actions/cache`, keyed by README content hash). Per ADR 0001 the LLM is never load-bearing: any failure falls back to the cached Summary, then the raw repo description — the build never fails because of the LLM.
- The only hand-authored material is **Seed Content** in `site.config.json` (name, tagline, pitch, experience epochs, contact links) plus `static/resume.pdf`.

## The matter system

The front end ships two readings of the same HTML, chosen before first paint by a probe in `<head>`:

- **Calm site** (no JS, `prefers-reduced-motion`, no WebGL, or a viewport under 820px) — a plain scrolling document. Everything is legible; nothing is hidden.
- **Matter site** — four fixed pages. Every heading marked `.mt` is rasterized off-screen into a point cloud and drawn by `static/matter.js` as one `gl.POINTS` call over a single 6,000-particle buffer that is sized once and never reallocated. Navigating runs one choreography over that buffer: a caret consumes the current page's glyphs, carries the grains across, and emits them into the next page's letterforms. Between pages the grains idle in an hourglass.

Two constraints the design brief calls out and the code enforces:

- **Type below ~26px cannot be built from matter.** The sample grid is `fontSize / 14` clamped to 3–6px; finer type has no room for a grid finer than its own strokes. Small copy is DOM text that fades in as the caret passes. Watch CSS specificity here — a rule that shrinks an `.mt` element below the floor makes it dissolve.
- **Performance is the named failure mode.** No allocation during a transition, no per-frame `getBoundingClientRect` (re-anchor on resize and page change only), phase timing integrated on clamped `dt` so a throttled tab cannot skip the choreography, and an adaptive pixel-ratio drop if the first full transition misses ~48fps.

WebGL is hand-rolled rather than pulled from a 3D library: one draw call does not justify the dependency.

## Topic Overrides

Steer the site from GitHub, no code changes:

| Topic on a repo     | Effect                                                                  |
| ------------------- | ----------------------------------------------------------------------- |
| `portfolio-feature` | Always a Featured Project, regardless of score — even if it is a fork   |
| `portfolio-hide`    | Never appears on the site at all (beats `portfolio-feature`)            |

Forks and the profile repo (`Jakhmola/Jakhmola`) are otherwise always excluded. The fork escape hatch exists because GitHub flags `career-ops` as a fork (parent deleted) even though it is active original work.

## Development

Node ≥ 20, zero runtime dependencies.

```sh
npm test                                # node:test, fully offline (fixtures)
npm run build                           # live build from the GitHub API -> dist/
node src/build.js --fixtures test/fixtures   # offline build from fixture JSON
```
